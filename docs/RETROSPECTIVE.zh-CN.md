# 项目复盘

KeyVault Personal 是给自己用的本地密码库。开源是为了把完整链路摊开：加密格式、桌面壳、移动壳、测试和发布，而不是再做一个带账号的云产品。

## 需求是怎么收口的

产品形态一开始就定成单用户、离线、主密码不可恢复。后来补的是分层条目（站点 / 账号 / 绑定）和标签分类。标签没有另起数据结构，沿用已有的 `tags[]`，旧文件缺字段时读成空数组。新建条目至少 1 个标签，最多 3 个；列表筛选和搜索是 AND。

明确不做的事：云同步、账号、支付、后台。国密也不在当前范围——实现是 PBKDF2-HMAC-SHA512 + AES-256-GCM。电脑故障时的可读副本走打印预览：确认前不写文件，确认后才出 PDF/图片，那是明文。

## 加密格式

文件头固定为 `[Salt 16][IV 12][AuthTag 16][密文]`。桌面走 Node `crypto`，Android 走 Kotlin `PBKDF2WithHmacSHA512` + `AES/GCM/NoPadding`。两边数字必须一致，否则导入会直接失败。导出的 `.kvault` 是密文拷贝，不是明文。

兼容迁移写在加载和导入两条路径上：没有 `accounts` 的旧条目会折成默认账号，没有 `tags` 的条目会变成空数组。

## 发布和验收

仓库同时推 GitHub 和 Gitee。CI 跑 `npm test` 和 Windows 构建；打 `v*` 标签时再打便携 `.exe`。开发模式曾经把本地 TypeScript 包外置，生产启动会找不到模块，所以主进程现在把 `@keyvault/core` 打进包里。

标签功能的手动验收用隔离的 user-data 目录做，避免碰到真实保险库。

## 还没做完

Android 工程是本地生成的，不进 git。加密参数已经对过，也写了格式测试，但真机上的双向导入导出还要实际装一次才能摘掉「实验性」。macOS / Linux 打包、空闲锁定、标签重命名删除都还没做。
